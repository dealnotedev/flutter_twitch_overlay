# Bundled music tools

From the repository root:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\download_tools.ps1
```

This downloads and verifies the official Windows x64 releases of `yt-dlp.exe`
and `deno.exe`, then builds our minimal `ffmpeg.exe`. It no longer downloads
the large gyan.dev essentials bundle. If yt-dlp and Deno are already installed:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_ffmpeg.ps1
```

The build script downloads checksum-pinned FFmpeg 9.0.2 and a private MSYS2
environment under `build/ffmpeg-minimal`. It installs GCC, make, NASM, pkgconf,
diffutils and static LAME there. No administrator install or persistent PATH
change is needed. The first run needs internet access and takes several minutes;
later runs reuse sources, tools and object files. Windows `tar.exe` is required.
MSYS2 packages are signed; the compiler/LAME versions and complete FFmpeg
configuration are recorded in the generated `ffmpeg-build.txt`. Package versions
can change on a fresh bootstrap, so this is not a bit-for-bit reproducible build.

## Runtime scope

`YtDlpMusicTrackFetcher` downloads one YouTube format (`ba/b`) and asks yt-dlp
to extract MP3 at quality 0. FFmpeg only reads files already downloaded by yt-dlp.
The minimal build enables:

- AAC, Opus, Vorbis and MP3 decoding, and the libmp3lame MP3 encoder;
- MP4/M4A, WebM/Matroska, MPEG-TS, Ogg, ADTS AAC and MP3 input;
- MP3 output and container remuxing needed by yt-dlp's DASH/HLS/timestamp fixups;
- audio format conversion/resampling, local file and pipe protocols.

Video decoders/encoders, GPU acceleration, capture devices, network protocols,
ffplay and ffprobe are omitted. Audio can still be extracted from a combined
video/audio file. This is not a general-purpose FFmpeg distribution and does not
support FFmpeg downloading URLs itself, embedding thumbnails or subtitles.
Normal YouTube HTTP/DASH/native HLS downloads remain handled by yt-dlp.

`ffprobe` is not required for this flow. yt-dlp's `get_audio_codec` falls back to
`ffmpeg -i`; YouTube title/duration metadata comes from yt-dlp's JSON output.
HLS fixup may log a harmless missing-ffprobe warning before using its fallback.
Keep normal FFmpeg log messages and codec names enabled for this detection.

## Packaging

Executables and build metadata are ignored by Git. The Windows CMake install
explicitly copies only `yt-dlp.exe`, `deno.exe`, `ffmpeg.exe` and the two license
files, plus `ffmpeg-build.txt` when present. Build metadata is generated by
`build_ffmpeg.ps1`; older downloaded FFmpeg runtimes can be packaged without it.
The install also removes a leftover `tools/ffprobe.exe` from
an incremental release. The build script removes the obsolete probe from the
repository's `tools` directory after successfully building FFmpeg.

For an OBS installation, copy the same six runtime files to
`<OBS root>\obs-plugins\64bit\flutter_obs_tools\` and remove the old ffprobe there.
Build dependencies and source archives belong in `build/`, never in the release.

FFmpeg is built as LGPL 2.1-or-later with LGPL LAME and no GPL/nonfree components.
Both license texts are included. Keep the corresponding sources and build recipe
available with binary distributions: FFmpeg's source archive, build objects and
static libraries remain in `build/ffmpeg-minimal`; the LAME package source recipe
is linked from `ffmpeg-build.txt`. Static linking avoids shipping MinGW/MSYS2 or
LAME DLLs; the build checks its imported DLL names.

## Verification

Use a separate full FFmpeg only to generate fixtures and independently decode
the resulting MP3 files:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\test_ffmpeg.ps1 -ReferenceFfmpeg D:\ffmpeg\ffmpeg.exe
flutter test test/music/music_tool_paths_test.dart test/music/yt_dlp_music_track_fetcher_test.dart
```

The integration test uses the bundled yt-dlp and a temporary local-only Deno HTTP
server. It checks Opus/WebM, Vorbis/WebM, fragmented AAC/M4A, ADTS AAC, existing
MP3, H.264/AAC MP4, VP9/Opus WebM and native HLS with MPEG-TS fragments. Each case
must produce a decodable MP3 of the expected duration with no ffprobe available.
Logs and fixtures remain under `build/ffmpeg-test-*`. No YouTube access or cookies
are needed. Run it again when upgrading yt-dlp or changing the build profile.
